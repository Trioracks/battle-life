# Package Two — Round Topics and Social Content Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Темы раундов с судьёй-автором, небольшая жизнь сообщества/форума, эмоциональная публикация героя и полный контентный/интеграционный контроль демо.

**Architecture:** Создание темы подключается к доменному событию нового раунда; небольшие заранее сгенерированные сценарии реакций публикуются едиными игровыми часами. Количество реакций, шаблоны и медиа разделены. Существующие social-wall, forum и безопасная очередь реакции героя остаются точками интеграции.

**Tech Stack:** Existing JS ES modules/Node tests/JSON catalogs/Three.js avatars, local image assets. ImageGen для создания растровых обложек при выполнении соответствующей контентной задачи, не внешняя генерация в runtime.

**Spec:** [Единая постановка](../../backlog/2026-10-12-implementation-handoff-v2.md), [посев/споры](../../backlog/2026-10-12-pairing-and-community-timeline.md), [формулы](../../backlog/2026-10-12-news-reactions.md), [банк реплик](../../backlog/2026-10-12-social-reaction-bank.md), [темы/брифы](../../backlog/2026-10-12-round-topic-catalog.md).

- После P0–P5 и просмотра автором пакета. Порядок всех планов — §6 постановки; S4 может выполняться независимо от UI, но наличие внешних записей не обещается.
- Не создавать большую соцсимуляцию, рост аудитории, ручной редактор всех постов/комментариев или новые внешние сервисы. Небольшие сценарии событий достаточны.
- Доменные события/публикация — из T2/T3, контроль доступа/персонажи — R2. Не дублировать часы, личности, профили и результаты.
- Не менять опубликованную тему/пост/картинку при повторном открытии либо обновлении банка. Новые каталоги версионировать, старые записи сохранять.
- Работа/медиа/кэш на D:. Если инструмент настаивает на большом кэше C:, остановить только эту контентную операцию и сообщить ограничение. Источники/исходную таблицу не изменять.
- Все реальные ожидания/отсутствующие материалы отражать в журнале; не закрывать карточку по фикстуре или одному макету.

## Review Focus

1. Тема/автор различаются между анонсом, судьёй и созданием текста — S1, одна persisted тема на RoundKey.
2. Ажиотаж путается с негативностью либо будущие комментарии видны в счётчиках — S2, примеры 100/80 и 100/20 плюс calendar visibility.
3. Везде одни реплики, придуманные цитаты/события или случайные незнакомые авторы — S2/S3/S5, фильтры контекста/источников и 50 работ.
4. Камера/автопост повторяются, прерывают работу или сообщают ложную победу — S3, safe queue, failure/reload и результат вылета.
5. Брифы/заглушки считаются готовыми медиа, геройский голос присваивается NPC — S4/S5, manifest/rights/provenance/missingAssets и отдельный итог готовности.
