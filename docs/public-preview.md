# Public preview: запуск и разработка

Это облегчённый публичный исходный код `Trioracks/battle-life`. Публичная ветка
для публикации — `master`. Полный закрытый рабочий каталог и его история сюда
не переносятся. [Манифест происхождения](public-source-provenance.json) фиксирует
исходный коммит `b773a928a5de456b5edf3e0521d8c5223cc352ad` и публичную базу
`eb6f1a6725a4fa15764e3ddea0d47c607a376bed`; это происхождение снимка, а SHA
новой веб-сборки — её фактический публичный HEAD.
Обновление от 18 октября 2026 года записано отдельным элементом `updates`:
локальный HEAD `60f5187bdc6f54cf64d62d4d9fcef13bf4b48aa3` и точный хешированный
инвентарь дополнительных рабочих текстов. Исходное происхождение снимка сохранено;
рабочие изменения не выдаются за содержимое локального коммита.

## Чистое клонирование

Нужны Git (на Windows — Git for Windows с его Bash) и Node 24. Для `npm test` дополнительно нужен Python 3 со стандартной
библиотекой, без pip, Blender и внешних аудиофайлов. Для запуска, сборки и игры
Python не нужен. Установленные инструменты должны быть доступны через PATH.

На этом Windows-компьютере системный C: ограничен. Сначала в PowerShell:

```powershell
$env:TEMP = 'D:\Codex\Temp'
$env:TMP = 'D:\Codex\Temp'
$env:npm_config_cache = 'D:\Codex\Caches\npm'
$env:PLAYWRIGHT_BROWSERS_PATH = 'D:\Codex\Caches\ms-playwright'
New-Item -ItemType Directory -Force -Path $env:TEMP,$env:npm_config_cache,$env:PLAYWRIGHT_BROWSERS_PATH | Out-Null
git clone https://github.com/Trioracks/battle-life.git D:\Project\Battle-Life-public
Set-Location D:\Project\Battle-Life-public
node --version
npm ci
npm start
```

Откройте `http://127.0.0.1:4180/battle-life/`. Остановите свой сервер Ctrl+C.
Если 4180 занят, используйте `npm start -- --port 4181` и соответствующий адрес.
Не останавливайте чужой сервер, в частности существующий сервер на 4173.

Linux/macOS (CI использует собственный workspace и runner temp):

```sh
git clone https://github.com/Trioracks/battle-life.git battle-life
cd battle-life
node --version
npm ci
npm start
```

В Codex откройте именно клонированную папку через Open folder, прочитайте
`AGENTS.md`, создайте ветку `codex/<короткая-тема>` от актуального master.
Внесите изменение, проверьте, создайте PR, дождитесь независимого ревью и
успешных проверок точного SHA, затем обновите master через merge. Не вливайте
сохранённую полную ветку разработки: переносите только проверенные изменения
в этот публичный репозиторий. Не используйте закрытый каталог как источник
клонирования публичной истории.

## Проверки

В отдельной консоли из корня клона с теми же переменными кеша/temp:

```sh
python --version
npm test
npm run audit:source
npm run build:preview
npm run audit:site
```

Тесты ищут Python 3 в `python3`, `python`, затем Windows `py -3`. Если Python
не найден, установите Python 3 либо задайте `BATTLE_PYTHON` как путь к одному
исполняемому файлу, например в PowerShell
`$env:BATTLE_PYTHON = (Get-Command python).Source`. Не включайте аргументы в эту
переменную. `python --version` выше — удобная предварительная проверка; если
у вас только `python3`/`py`, используйте `python3 --version`/`py -3 --version`.
Публичный набор исключает явно перечисляемые при запуске файлы из `test/local-assets`:
физические аудио/Blender-ассеты, Windows-архивирование и офлайн DSP с FFmpeg.
Сами чистые проверки геометрии/строителей Python выполняются публично.
Логика пяти голосов, ротации, сохранений и кривых навыков входит в `npm test`;
проверки `.test.mjs` также обнаруживаются. Генерируемые тестами файлы остаются в
заданном вызывающей стороной TEMP/TMP вне дерева исходников.

Проверка новых коммитов перед публикацией (включает все промежуточные деревья):

```sh
node tools/audit-publication.mjs history --base eb6f1a6725a4fa15764e3ddea0d47c607a376bed --head HEAD
```

Для нового PR можно взять `git merge-base origin/master HEAD` как `--base`.
Нужна полная Git-история, не shallow clone. Аудиты завершаются с ненулевым кодом
при запрещённом содержимом или превышении лимитов. Публикуется только
`dist/public-preview` (до 350 MiB всего, до 95 MiB на файл), с путями под
`/battle-life/`. `release.json` содержит версию, полный SHA публичной сборки,
исходный коммит снимка, профиль и время; меню показывает короткий SHA.

Браузерная проверка Task 6 использует закреплённый Playwright из `npm ci`:

```sh
npx playwright install chromium
npm run qa:preview -- --root dist/public-preview --output-dir ../battle-life-preview-qa
```

На Linux CI для системных зависимостей используется
`npx playwright install --with-deps chromium`. Сначала проверьте свободное место
и настройки кеша. На этом Windows-хосте браузеры должны скачиваться на D:.
QA запускает свой сервер для собранного артефакта и новый браузерный контекст.
Вывод QA храните вне исходного дерева и `dist/public-preview`; он не входит в
Git, source-аудит или Pages. Не используйте профиль браузера игрока.

## Необязательный локальный аудиопак

Публичный режим `public-preview` работает без аудиопака. Надпись в игре:
«Музыка и вокал отключены в тестовой веб-версии». Каталожные ID и совместимость
сохранений остаются; процедурные эффекты интерфейса и комнаты работают.

Если у вас уже есть полный легальный набор локальных файлов, задайте внешний
абсолютный корень с исходной структурой `assets/...` и `stems/...`:

```powershell
npm start -- --profile local-full --asset-root D:\Media\Battle-Life-local
```

Для локального запуска также можно создать в корне клона игнорируемый
`.local-audio.json`:

```json
{"assetRoot":"D:/Media/Battle-Life-local"}
```

Тогда запускайте `npm start -- --profile local-full`. Обычный `npm start`
всегда остаётся публичным. Строгий `audit:source` проверяет и игнорируемые файлы
и отклоняет активный `.local-audio.json`: проверки публикации выполняйте в чистом
клоне без этого файла. Чтобы локальный запуск не добавлял настройки в дерево
исходников, предпочтителен показанный выше параметр `--asset-root`.
Физические проверки всего локального набора запускают
отдельно: `npm run test:local-assets -- --asset-root D:\Media\Battle-Life-local`.
Для них нужны все исходные локальные файлы, включая Blender-источники;
Windows-проверка установщика выполняется только на Windows. CI этот набор не
запускает. Для новых офлайн DSP-проверок нужен FFmpeg с фильтром Rubber Band
(исполняемый файл в PATH либо `FFMPEG_PATH`). Для проверки исходного GANS-демо
в локальном корне также нужен его исходный `artifacts/gans-mix-session/recipe.json`.
Не добавляйте аудиопак, настройки, stems, Blender, архивы, секреты,
кеши и QA в публичную Git-историю или Pages; не маскируйте их расширения.

## Тестерам

После успешной публикации откройте [сайт](https://trioracks.github.io/battle-life/).
Сохранение только локальное для браузера и origin; автоматической синхронизации
нет. Создайте героя, зайдите в квартиру и компьютер, откройте браузер, форум и
турнир, проверьте подготовку трека, сохранение и продолжение после перезагрузки.

Для [сообщения об ошибке](https://github.com/Trioracks/battle-life/issues)
приложите скриншот меню с версией/SHA и проблемного экрана, браузер/ОС, размер
окна, точные шаги, ожидаемый и фактический результат. Если ошибка загрузки —
добавьте текст ошибки из консоли/Network без личных данных. Укажите, воспроизводится
ли она в чистом отдельном профиле; свой игровой профиль для этого не очищайте.
